# Security Doctor — The Checklist

The scored audit — 45 manual checks (items 1–33 structural + 40–46 business-logic + 47–51 server-side/disclosure, verify by hand/probe) + a 6-tool **scanner layer** (domain 9, items 34–39; see `tooling.md`). Each item: what to verify, how to detect the gap (grep or live probe), and the fix-template number ([T#] in `fix-templates.md`). **Report a checkbox as ✅ only with file:line evidence or a live-probe/scanner result — never from "looks fine."** Status values: ✅ done · ❌ gap · ⚠️ partial/hardening-only · ⏭️ n/a (say why).

Items marked ⚙ are stack-specific (Supabase/Vercel) — translate the intent for other stacks; the underlying law (in `knowledge-base.md`) is portable.

## Transport & headers
1. **HSTS** — `curl -sI <prod-url> | grep -i strict-transport`. Vercel default on custom domains; flag only if a custom server strips it.
2. **Secure cookie flags** — every `Set-Cookie` carries `Secure; HttpOnly; SameSite`. Grep `Set-Cookie`, `cookies.set`. UI-hint cookies readable by JS may skip HttpOnly deliberately — note it, don't fail it.
3. **Security headers present** — `X-Content-Type-Options: nosniff`, `X-Frame-Options` (SAMEORIGIN if the app iframes itself, DENY otherwise), `Referrer-Policy`, `Permissions-Policy`, `base-uri`, `object-src 'none'`. `curl -sI` + read `vercel.json`/server config. [T10]
4. **CSP** — enforcing, no `unsafe-inline` in `script-src` where achievable; `report-uri` wired; a report row under `disposition:"enforce"` = a real regression. Report-Only → collect → enforce. [T10]

## Auth flows
5. **Sessions reset on password change** — `signOut({scope:'others'})` after in-app change; `{scope:'global'}` on emailed reset. Grep `updateUser`, `signOut`. Verify the reset flow actually OFFERS a set-new-password screen (`PASSWORD_RECOVERY` handler → password form → `updateUser({password})`). ⚠️ **Grep the LIVE-served JS, not the local workspace** — a stale workspace makes "no `updateUser` anywhere" a false positive when the fix already shipped. [KB §c]
6. **Reset links expire + redirect allowlist** — Supabase default; verify the redirect allowlist covers app + beta hosts. Standalone `/reset` page, synchronous token capture, `detectSessionInUrl:false`. [KB §c]
7. **Failed-login lockout + reset throttling** — DB-backed counter, lock ~8/15min, throttle resets ~3/hr, page the owner at 5. **MUST fail OPEN.** [T7]
8. **User enumeration** — audit sign-in/reset/signup messages. Deliberate exposure (semi-public usernames) is a documented UX call — check code comments before "fixing." Email flows answer uniformly. [KB §c]
9. **2FA/MFA server gate** ⚙ — if 2FA exists, the SERVER gate is the security (aal2 on every privileged endpoint), not the modal. **Fail CLOSED.** Do NOT gate the whoami endpoint. Backup-code tables = RLS-on-no-policies + grants revoked. [T8]
10. **Session robustness** ⚙ — Supabase JS: in-memory serializing lock (not `navigator.locks`, not no-op), JWT decoded from localStorage on boot, `refreshSession` on foreground. Grep `createClient`, `getSession`, `getUser`. [KB §c]

## Payments (skip section if no payments — say so)
11. **Verify payment webhooks** — Stripe signature on every webhook route; other webhooks Ed25519/HMAC. Grep `constructEvent`, `verify`. Handle `charge.dispute.created/.closed` (unhandled dispute = auto-lose). [KB §h]
12. **Prices server-side** — client NEVER sends an amount; server derives price from the product/tier row. Grep checkout routes for `amount` in request bodies. Test key on Preview only, live on Production. [KB §h]

## AI surfaces (skip if no LLM)
13. **Prompt-injection fencing** — any route putting outside text (emails, SMS, transcripts, reviews, form fields) into an LLM must delimit it, label it untrusted DATA, forbid promises, ignore staff-impersonation. **Check interpolations into the SYSTEM prompt** (a sender name is a vector — sanitize to a tight charset). [T9]
14. **Cap AI usage + bound model spend + keep regulated data out of prompts** — per-request caps + spend-shaped limits on anything a stranger can trigger; a **per-identity and per-tenant model-spend cap** plus a **global daily budget breaker**, so one heavy/abusive user — or a looping agent — can't run up the provider bill (a prompt loop is a money bug, not just a latency bug); and **no PII / card / health / other-tenant data in prompts that leave your network** — strip or tokenize before the call, because the prompt is an egress channel and often a retained one. Human-in-the-loop for money/credential/policy actions: the model's output drafts, it never directly fires an irreversible action. Detect: grep model-call sites for a spend/rate guard and for raw PII or a whole `req.body` interpolated into the prompt; confirm a budget/anomaly alert exists. [KB §f/g]

## Request hygiene
15. **Limit request size** ⚙ — Vercel's 4.5MB default counts; flag custom servers only.
16. **Sanitize before storing/rendering** — `esc()`/framework escaping on every user string reaching innerHTML; note `dangerouslySetInnerHTML`. React escapes by default. Grep `innerHTML`, `dangerouslySetInnerHTML`.
17. **Lock down CORS** — no `*` on credentialed routes; postMessage origins EXACT-match allowlists (never `endsWith('.domain')`). Grep `Access-Control-Allow-Origin`, `postMessage`, `origin`.
18. **Whitelist upload types + treat uploads as hostile bytes** ⚙ — presigned uploads carry an enforced contentType; bucket MIME allowlist (Supabase Storage matches `allowed_mime_types` EXACTLY — strip `;codecs=`). Beyond MIME: **sanitize or reject SVG** (embedded `<script>` = stored XSS); serve user uploads from a **separate sandboxed origin** (not the app's cookie domain) with `X-Content-Type-Options: nosniff` + `Content-Disposition`; sanitize filenames (no traversal, no control chars) and store under a server-generated key, not the user's name; where an upload is shared with or downloadable by other users, **scan it** (AV / content scan) before it is ever served. Detect: upload an SVG with a script and fetch it; upload a `../../x` name; check whether the serving origin shares the auth cookie; confirm a scan runs on anything that leaves one user and reaches another. [KB §h, §k]

## Surface area
19. **Admin routes gated** — every admin page behind middleware + server-side role check (+2FA where it exists); no debug/test routes reachable without a role check. Middleware runs before filesystem; normalize the pathname. [T11]
20. **Server-side admin re-check** — every privileged endpoint resolves the caller server-side and checks role by an **un-forgeable auth column** (`auth_id`), never a client-writable field, never a client "isAdmin" flag. Verify with a real 200/403, not "not 403." **Gate before validate:** the role check runs before any op/action-name validation — a `400 Unknown op` returned to a non-admin enumerates the op vocabulary. **And run the client-flag spoof test:** set the client's admin flag in devtools (`currentUser.isAdmin = true`) and list every admin PAGE that then renders — any page that reads the DB with the user's own JWT (not through a gated `/api` route) is only as private as RLS makes it; in-app admin UIs are the usual offender, the separate admin panel usually isn't. [T5, T13, KB §b]
21. **Remove pre-launch test scaffolding** — grep `TEST BYPASS`, `ADMIN LOCATION OVERRIDE`, unauthenticated test endpoints that spoof state, payout bypasses. `git rm` before launch.
22. **CSRF** ⚙ — mostly n/a for bearer-token APIs; REQUIRED if any state-changing endpoint authenticates via cookies alone.
23. **Directory listing** ⚙ — n/a on Vercel; check on any custom static host.

## Data & visibility (the Supabase core — often where the real gaps are)
24. **Anon write lockdown** ⚙ — anon role has no INSERT/UPDATE/DELETE except explicitly-granted analytics/feedback. Live-probe every table (send a REAL column value; read the 42501 MESSAGE). Catalog-generated revoke, not a typed list. Also strip the default `GRANT ALL` residue — `TRUNCATE`, `TRIGGER`, `REFERENCES` on every table for both client roles (unreachable via PostgREST, but it's the ceiling and nothing needs it) — plus `ALTER DEFAULT PRIVILEGES` so new tables don't regrow it. Start from the **grant inventory triad** (T13 §A) rather than probing blind. [T1, T2, T13]
25. **Column-level exposure** ⚙ — no bearer tokens / PII / push-subscription keys readable by anon **or by a signed-in non-admin** on public-read tables. **If signup is open, `authenticated` is a public role too** — the users table's email / admin flag / auth id were anon-locked and authenticated-open for months. Probe PER COLUMN (`select=*` 42501 is the column trap) **as both roles**. Table-level revoke + named re-grant; the app's OWN row comes back through a DEFINER `my_profile()` RPC (ship the client with a "RPC missing" fallback first so migration order can't break sign-in). Before revoking a users-table column, run the policy inventory (T13 §C) — every other table's policy that sub-selects that column runs as the caller and will throw. [T3, T13]
26. **RLS on sensitive tables** ⚙ — no `USING(true)`; owner-scoped policies with `WITH CHECK`; service-role-only tables = RLS-on-no-policies + grants revoked. Query `pg_policies WHERE qual='true'` — and **drop open SELECT policies by inspection, not by name** (T13 §B): permissive policies OR together, so one `USING (true)` left beside a scoped one keeps the table open. **The app-id trap:** if the app's users table has its own `id` and stores the auth uid in `auth_id`, then every `user_id` / `requester_user_id` column holds the APP id — a policy written `user_id = auth.uid()` silently matches nothing, someone adds an open policy next to it "to make it work", and the scoped one becomes decoration. Key policies on a DEFINER `me()` helper. Probe as a signed-in non-admin and **verify ownership of every visible row with the service key** — a QA account that is staff/vendor on a claim sees that claim's rows legitimately; record what the probe account is. **An empty result is not proof** — `0 rows` on an empty table reads identical to a scoped policy. [T4, T13]
27. **SECURITY DEFINER RPC exposure** ⚙ — every DEFINER function revoked from `anon, public`, `search_path` pinned, `ALTER DEFAULT PRIVILEGES ... REVOKE EXECUTE ... FROM anon`. Probe `/rest/v1/rpc/<fn>` with the anon key. [T5]
28. **Privilege-escalation columns** ⚙ — `is_admin`/`banned`/`credit`/`points` not writable by `authenticated` or `anon` (column REVOKE); optional BEFORE-UPDATE guard trigger; anon INSERT on users/profiles table revoked. Probe `PATCH is_admin` as a signed-in non-admin. **Membership tables are escalation columns too:** a `staff_members` / `team_members` / `collaborators` row grants data access through `is_staff_for()`-style policies — its INSERT/UPDATE/DELETE must be owner-or-admin only, never self-service (`WITH CHECK (claim_id IN (owner's claims))`). Also grep the client for privileged writes that a server path already performs (a client `UPDATE promo_codes SET active=false` "for test mode" let any user kill any gift card). [T6, T14, KB §b]
29. **Metered/unauthenticated endpoints throttled** — routes that email/SMS/spend need a verified session or a DB rate-limit; unauthenticated collectors (CSP, error log) throttled per IP, always 204. Grep `notify`, `send`, service-role routes. [T12]
30. **Log security events + alert — and never log secrets/PII** — auth bursts, 403s on fences, CSP reports flow into the app's error pipeline → owner alert (no pipeline = a gap on its own). **The logs are also a target:** no passwords, tokens, full card numbers, API keys or raw PII in logs or error traces — redact before logging; a log aggregator is a breach surface. Detect: grep log/`console` calls for `password`/`token`/`authorization` or a whole `req.body` dumped. [T12, KB §k]

## Supply chain & CI
31. **No secrets in git history** — `gitleaks` with `fetch-depth: 0`; rotate anything found; `.gitleaks.toml` allowlists public-by-design keys.
32. **Dependency scan** — `npm audit --audit-level=high`; committed lockfile.
33. **Security tests wired into CI** — the anon-probe harness + source ratchet run in an actual CI job; every new assertion FAILS against the unfixed state first. [T2]

## Automated scanner layer (domain 9 — run alongside the manual checks; catches classes the checklist structurally can't. Full detail in `tooling.md`)
34. **Supply-chain malware** — Socket (behavioral) or OSV-Scanner on every dependency change. `npm audit` only knows disclosed CVEs; this catches typosquats / hijacked / malicious-install-script packages with no advisory yet. [Tooling §1]
35. **Deep SAST on own code** — Semgrep (`p/javascript p/nodejs p/owasp-top-ten` + stack rulesets) taint-tracks input→sink in your own routes. We have no SAST otherwise. [Tooling §2]
36. **Verified secrets** — TruffleHog `--only-verified` / `--results=verified,unknown` live-validates keys (a leaked service-role key bypasses all RLS). Layer on top of gitleaks, don't replace. [Tooling §3]
37. **Live DAST** — Nuclei (`-tags exposure,misconfiguration`) against every deployed host; the only *external* probe (exposed `.env`, DB-studio leak, headers-as-served). Own/authorized targets, weekly. [Tooling §4]
38. **CI / Actions hardening** — zizmor on `.github/workflows/`: unpinned actions (SHA-pin), `${{ github.event.* }}` injection, over-broad `GITHUB_TOKEN`, `persist-credentials`. Your CI holds prod secrets = attack surface. [Tooling §5]
39. **LLM red-team regression** — promptfoo redteam suite per tool-using agent route, so a prompt edit can't silently reopen the fencing. Turns manual fencing into a CI gate. [Tooling §6]

## Business logic & money/state abuse (items 40–46 — run in the main audit pass, not the launch pass)
*The logic layer the structural checks (1–33) and the scanners (34–39) both structurally miss: flaws in the gap between what you specified and what the server will actually accept. The highest-$ bug class, the least visible in code review, and present in **every** app that moves money, holds multi-user/tenant data, or meters a resource — not just payment apps. Skip only if the app has no money, no credits/points, no multi-user data, AND no metered limits (rare). Attack each flow as a **state machine** and fire probes **concurrently** — these bugs are invisible to a serial pass.*
40. **State-machine integrity — no step-skip, no replay** — every multi-step flow (signup→verify→pay→provision, cart→pay→confirm, KYC, onboarding, approval) enforces step order AND completion **server-side**; a terminal action whose prerequisites aren't recorded is rejected. Non-idempotent money/state actions carry an idempotency key or a unique constraint so the second attempt fails at the DB. Detect: replay the final step (`/confirm`, `/activate`, `/provision`, claim-reward) with prerequisites missing, and fire the same one-time action twice **concurrently** — expect a 4xx both times. **Fail CLOSED.** [T15, KB §j]
41. **Server derives every amount — the client proposes nothing that becomes money** — price, quantity, currency, discount, tax, shipping and the final total are computed server-side from trusted rows; the client sends only ids + intent (product id, qty), never values. (Generalizes #12 from "price" to the whole cart.) Detect: grep order/checkout/charge/invoice routes for `amount|price|total|unit_price|currency|discount|qty` read from the request **body**; probe negative / zero / float / oversized quantity, a client-supplied unit price, a swapped currency code, and a product id changed after the price lookup. Any one honored = gap. [T15, KB §j]
42. **Discount / credit / coupon / referral logic is atomic + bounded** — each code or balance change is single-use where intended (atomic decrement or a unique-redemption row, **never** check-then-write), scoped to the right product/user/tenant, non-stacking unless designed, expiry checked server-side, and a negative or >100% effect impossible. Store-credit / loyalty / referral balances can't go negative or be minted by replaying the grant. Detect: apply one code twice **concurrently** (race), stack two, tamper an expired code's date, apply a product-A code to product-B, replay a referral-credit grant. [T15, KB §j]
43. **Refund / payout / withdrawal can't exceed or outrun the payment** — refundable = captured − prior refunds, computed server-side; the balance check and the debit are **one atomic transaction** (never check-then-pay); a payout destination can't be changed in-flight and re-triggered. Detect: refund more than paid; double-refund via concurrent requests; withdraw the same balance twice concurrently; change payout account then replay. [T15, KB §j]
44. **Tenant / ownership boundary on every record, aggregate, and bulk op** — every object a request reads or writes is re-scoped to the caller's tenant/org/account **server-side**, including hidden body fields (`tenant_id`, `org_id`, `account_id`), nested objects, batch/bulk endpoints, exports/reports, and webhook-triggered jobs. (The logic layer beneath #26 — RLS scopes direct reads with the user's JWT; a service-role route, an aggregate, or an export runs RLS-exempt and must re-scope in code.) Detect: substitute another tenant's id in a hidden field; request an export and verify row scoping; hit a bulk endpoint with mixed-tenant ids. Return 404 cross-tenant, not 403. [T16, KB §j]
45. **Quota / plan / entitlement enforced on the server at the metered action** — free-tier limits, seat counts, feature flags, usage caps and trial status are checked server-side **on the action**, reading the subscription/plan row, never a client claim. (Server-side cousin of #20.) Detect: call the gated action directly with the paid feature "off" (grep for toggles that only change UI — `/api/export`, premium endpoints); exceed a seat/row/usage cap via the API; keep using a feature after flipping the trial flag in the client. [T16, KB §j]
46. **Anti-automation on abuse-prone + money-adjacent flows** — account/invite creation, referral grants, reviews/votes, checkout attempts, and anything that costs money or pollutes data per call has a per-identity **and** per-IP limit, plus a verification step where the payoff is high (free credit, referral payout); the reward side is idempotent so farming one identity N times nets one payout. (Extends #29 from infra endpoints to business abuse.) Detect: script N rapid creations/submissions/redemptions; confirm throttle **and** single-payout. [T12, T15, KB §j]

## Server-side & disclosure surfaces (items 47–51 — OWASP classes the structural checks above don't name; run in the main audit pass)
47. **SSRF — no server-side fetch of a client-controlled URL without an allowlist** — any route that fetches a URL the user supplies (link preview, image-from-URL, avatar import, outbound webhook delivery, PDF/screenshot render, OAuth/OIDC discovery, "import from `<url>`") validates the target against an **allowlist of hosts + schemes**, blocks private / loopback / link-local / cloud-metadata ranges (`127.0.0.0/8`, `10/8`, `172.16/12`, `192.168/16`, `169.254.0.0/16` incl. `169.254.169.254`, `::1`, `fc00::/7`), disables redirects (or re-validates every hop), and never reflects the raw response/headers back. Detect: grep for `fetch(`/`axios`/`got`/`request(` taking a `req.body`/`req.query` URL; probe with `http://169.254.169.254/…`, `http://localhost:<port>`, and a 302 to a private IP. **Resolve-then-connect (pin the validated IP)** to beat DNS rebinding. [T17, KB §k]
48. **No open redirect** — any post-login / post-action redirect (`?next=`, `?returnTo=`, `redirect_uri`, `continue=`) only sends the browser to a **same-site relative path or an allowlisted host**, never to an arbitrary absolute URL from the parameter. An open redirect launders phishing and leaks tokens/`code` in the URL. Detect: grep redirect sinks (`res.redirect`, `location.href =`, `window.location =`) for a value read from query/body; probe `?next=https://evil.example` and `?next=//evil.example`. [T18, KB §k]
49. **No verbose errors / version disclosure in prod** — production responses never return stack traces, SQL text, internal file paths, framework/server version banners, or raw upstream error bodies to the client; a generic message + a server-side log id instead. Detect: trigger a 500 (malformed JSON, wrong type) and read the body + headers; grep for `err.stack`/`error.message` sent in a response, `X-Powered-By`, debug paths left on (`DEBUG`, `NODE_ENV !== 'production'` branches). Fix: a catch-all handler that logs server-side and returns `{error:'internal', id}`; strip `X-Powered-By`. [KB §k]
50. **Constant-time comparison of secrets** — webhook signatures, API keys, invite/reset tokens and any shared-secret check compare with a constant-time function (`crypto.timingSafeEqual`, `hmac.compare_digest`), never `===`/`==`, over fixed-length digests (HMAC both sides first). Detect: grep for `===`/`==`/`!=` against a `token`/`secret`/`signature`/`apiKey`/`hmac` variable; confirm signature checks use the provider SDK's verifier (constant-time) rather than a hand-rolled compare. Fix inline: HMAC both sides, then `timingSafeEqual(a, b)`. [KB §k]
51. **External auth / token issuance hardening** ⚙ — for "Sign in with `<provider>`" / OAuth / OIDC: a `state` (or PKCE) value is generated, stored, and verified on callback (missing `state` = login CSRF); the `redirect_uri` is an **exact** allowlist match (never prefix/substring); provider claims are trusted only after verifying the token signature + `aud`/`iss`/`exp`, and `email_verified` is checked before auto-linking an account by email. If the app **issues its own** JWTs/sessions: a pinned algorithm (no `alg:none`, no RS256→HS256 confusion), short expiry, a strong server-only secret/key, and revocation on logout + password change. Detect: inspect the callback route for `state`/PKCE verification and the `redirect_uri` check; for self-issued tokens, decode one and confirm `exp` + a non-guessable secret. [T18, KB §k]

---
**Scoring output:** a table `item · status · evidence (file:line, live-probe, or scanner result)`, then the gap list in priority order (live-fire / unauthenticated-escalation first), then fixes. Small fixes: implement in the same pass. Big/destructive: propose first. Record 0-finding scanner runs as evidence — and verify each scanner actually ran (a skipped/errored scan reads identical to a clean one).
